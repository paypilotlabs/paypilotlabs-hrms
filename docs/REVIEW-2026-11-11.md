## Naming options

**A) Metadata only (low risk).** `package.json` ×3 names and URLs, pyproject URLs and description (name stays `hrms`), `hooks.source_link`, optionally the Docker image tag and `FrappeHRLogo.vue` → `AppLogo.vue`. About 8 files. Nothing changes for bench, the database, URLs or existing sites.

**B) Full app rename to `paypilotlabs_hrms` (high risk).** Touches about 480 files: the package folder, 675 import lines, 262 dotted paths, `patches.txt`, hooks, 69 asset paths, vite bases, docker `install-app`, and `FORBIDDEN` in 9 repos. Existing sites need a data migration (Installed Application, Module Def, Patch Log; otherwise every patch re-runs). Every future security fix from frappe/hrms becomes a manual port.

**Recommendation: A.** Customers never see the package name. What they do see (title, logo, help links, About link) is fixed by A plus the branding fixes above. B costs a migration on every site and makes every future upstream merge much harder, for no visible gain.
